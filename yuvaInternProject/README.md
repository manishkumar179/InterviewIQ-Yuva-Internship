# 🧠 Project Overview

InterviewIQ is a web-based AI interview practice application planned to
provide candidates with a more interactive alternative to traditional
interview preparation.

Instead of only reading interview questions, a candidate can move
through a structured workflow:

``` text
🏠 Home
   ↓
🔐 Authentication
   ↓
⚙️ Interview Setup
   ↓
📄 Resume Upload (Optional)
   ↓
🔎 Resume Analysis
   ↓
🎤 Live Interview
   ↓
🤖 Evaluation
   ↓
📊 Performance Report
   ↓
📚 Interview History
```

The project is being developed incrementally through the YUVA
internship.

> **Important scope note:** Week 1 represents the planning and
> architecture phase. Week 2 represents the frontend implementation
> phase. Backend, database, AI processing, payment verification, and
> production security are treated as separate full-stack/integration
> responsibilities and are not falsely represented as completed merely
> because frontend API integration points exist.

------------------------------------------------------------------------

# 🎯 Problem Statement

Students, fresh graduates, interns, and job seekers often prepare for
interviews using static question banks, videos, notes, or informal mock
interviews.

These methods can help with theoretical preparation, but they may not
provide:

-   Realistic interview simulation
-   Consistent question-by-question practice
-   Personalized interview setup
-   Resume-oriented preparation
-   Voice-based interaction
-   Structured performance analytics
-   Detailed feedback
-   A history of previous interview attempts

InterviewIQ is proposed to provide a centralized web experience where
candidates can practice interviews and review their performance in a
structured way.

------------------------------------------------------------------------

# 💡 Proposed Solution

InterviewIQ is designed around a candidate-first workflow.

The candidate can select a target role, specify experience, choose an
interview mode, optionally provide a resume, participate in an
interactive interview, and review the resulting performance report.

### Core idea

> **Practice → Evaluate → Understand → Improve → Practice Again**

The application combines a clean frontend experience with planned
backend and AI services so that the product can evolve into a complete
full-stack interview platform.

The candidate participates in the interview simulation.

The system processes the interview responses.

The candidate receives performance analytics and improvement advice.

# 🧠 Week 1 Design Decisions

### Why React?

React was selected because InterviewIQ contains many dynamic and
interactive UI states.

### Why Vite?

Vite provides a fast development environment and modern frontend build
tooling.

### Why Tailwind CSS?

Tailwind CSS allows responsive styling and consistent UI development
using utility classes.

### Why Redux Toolkit?

Shared user information needs to be accessible across multiple
application views.

### Why Axios?

Axios provides a clean mechanism for communicating with REST APIs.

### Why Firebase?

Firebase provides a convenient authentication integration for Google
sign-in.

### Why Recharts?

The report requires visual representation of performance data.

### Why jsPDF?

Candidates should be able to save their performance reports.

  `POST /api/interview/resume`               Submit resume for analysis

  `POST /api/interview/generate-questions`   Request interview questions

  `GET /api/interview/get-interview`         Retrieve interview history

# 🧯 Challenges & Solutions

## Challenge 1 --- Multiple Interview Stages

**Problem:** Setup, live interview and report require different states
and responsibilities.

**Solution:** The workflow was divided into:

``` text
Step1SetUp
Step2Interview
Step3Report
```

**Result:** Each feature remains easier to understand and maintain.

------------------------------------------------------------------------

## Challenge 2 --- Shared User Information

**Problem:** User information can be required by different pages.

**Solution:** Redux Toolkit was used for shared user state.

------------------------------------------------------------------------

## Challenge 3 --- Dynamic Interview Interaction

**Problem:** Questions, answers, timer and voice states change during
the interview.

**Solution:** Interaction logic was separated into dedicated interview
components and local state.

------------------------------------------------------------------------

## Challenge 4 --- Making Analytics Understandable

**Problem:** A final numerical score alone is not enough.

**Solution:** The report combines:

-   Overall score
-   Skill evaluation
-   Trend chart
-   Question breakdown
-   Improvement advice

------------------------------------------------------------------------

## Challenge 5 --- Presenting Resume Data

**Problem:** Resume analysis can contain a large amount of information.

**Solution:** Projects and skills are presented using structured
sections and visual chips.

# 🔐 Security Considerations

The frontend follows the principle that sensitive operations should not
be trusted to the browser.

Important considerations:

-   Do not store private API keys in frontend source code.
-   Do not commit `.env` secrets to GitHub.
-   Validate user inputs.
-   Validate uploaded files on the server as well as the client.
-   Do not trust client-provided payment amounts or credit values.
-   Use secure authentication/session handling.
-   Handle unauthorized API responses.
-   Use HTTPS for deployed environments.
-   Keep AI/API secrets on the server.
